# G1 quickstart gate — both runs

Gate: fresh machine → running demo in ≤ 3 commands, ≤ 5 minutes.
Venue: fresh Hetzner **CX23**, Ubuntu 24.04, docker 29.1.3, destroyed after run 2.

## Run 1 — FAIL, and it is part of the record

Commands 1 and 2 passed (8s pull-and-run; 2s to accepting connections). Command 3
failed: `redis-cli` → **Connection reset by peer**.

**Cause:** `scripts/g1-quickstart-timing.sh` was missing
`-c pg_resp.bind_address=0.0.0.0`. pg_resp binds `127.0.0.1` (D6); inside a
container that is the *container's* loopback, which docker's port publishing cannot
reach. The script was written before the fix that went into the README and the CI
job, and never received it.

**Why the CI guard was green while a real host failed:** `quickstart-check` kept its
own inline copy of the three commands. That copy had the fix; the script did not.
Two definitions of the same commands is how green CI and a broken user path coexist
— now a standing rule in `CLAUDE.md`, and the job executes the script instead.

Verified run-command-only against the *same published image* before changing
anything: without the flag `SHOW pg_resp.bind_address` → `127.0.0.1` and the port is
unreachable; with it → `0.0.0.0`, `SET` ok, `GET` returns the value. **No rc2 was
needed.**

This run is kept because the gate did its job: it caught a broken first-user
command that every other check had missed.
